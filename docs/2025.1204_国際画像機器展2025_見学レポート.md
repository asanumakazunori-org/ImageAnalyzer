## 3. HALCON AIアシスタント機能（MVTec / LINX）

### 3.1 概要

* 対象：**HALCON 25.05 Progress Edition** の新IDE「**HDevelopEVO**」。

* 機能は大きく3種類：

  1. **チャット型アシスタント**

     * HALCONの使い方やオペレータ選択などを自然言語で質問。
  2. **エージェント機能**

     * IDEコマンド／シェルコマンドをAI経由で実行（ファイル操作、ビルド、実行など）。
  3. **コード補完の強化**

     * オペレータ名や構文をコンテキストに応じて補完。

* 利用するLLMについて：

  * **MVTec独自LLMというより、「外部LLMを選択して利用する前提」**。
  * ベンダ名（OpenAI, Google など）は明示されておらず、
    クラウド／オンプレ／ローカルモデルなどをユーザー側で構成する想定。
  * 「HALCON専用に事前学習されたLLM」が同梱されているわけではない。

### 3.2 できること（期待できる範囲）

※下記は「公式がうたう機能」＋「一般的なLLMの能力から見て現実的に期待できる範囲」の整理。

* **HALCONスクリプトの構文レベル理解**

  * if/while/for の流れ、サブルーチン、変数の依存など、
    **テキストとしてのコード構造の解析**は可能。
* **用途ベースのオペレータ選定支援**

  * 「ワイヤの輪郭を抽出したい」「サブピクセルでエッジを取りたい」等に対し、
    候補オペレータを挙げさせることができる。
* **簡易なリファクタ提案**

  * 処理の分割、重複コードの共通化、変数名の改善などの提案。
* **アルゴリズムの意図の説明**

  * コメントやコードを読ませて、「この処理は何をしているか」を自然言語で説明させる。
* **別言語へのたたき台生成**

  * 「このHALCON処理をPython/OpenCVで書くと？」といった形で、
    **参考レベルの移植コード**を出してもらうことは（LLMとして）可能。

### 3.3 できない／現時点では想定されていないこと

* **大規模設計書から骨子プログラムを自動生成**

  * ChatGPT（ブラウザ版）に長文設計書を渡して骨子コードを作らせる、という使い方は想定外。
* **リポジトリ全体の解析と自動変更**

  * Gitリポジトリを丸ごと解析して、依存関係を洗い出し、自動で一括リファクタ／コミット…といった
    「エージェント開発環境」レベルの機能は提供されていない。
* **HALCON以外のプロジェクト全体をIDE統合で扱うこと**

  * 基本はHALCON／HDevelopEVO内のスクリプト・プロジェクトを対象とする。

### 3.4 Copilot / ChatGPTとの位置づけ（イメージ）

* イメージとしては：

> 「Visual Studio での GitHub Copilot を、
> HALCON/HDevelopEVO に最適化して埋め込んだもの ＋ IDE/シェル操作エージェント」

* Copilot / ChatGPT との棲み分け（個人所感）：

  * **HALCON内のレシピ開発** → HALCON AIアシスタントが便利。
  * **C++/Pythonベースの装置ソフト全体** → Copilot / ChatGPT の方が向いている。
  * 両者を**プロトタイピング段階（HALCON）と実装段階（C++/Python）で使い分ける**のが現実的。

## 4. Gocator 4000/5000（LINX / LMI）

### 4.1 概要・特長

* 方式：**同軸共焦点ラインセンサ（Line Confocal）**。
* 特長：

  * レーザ光を光軸と同軸に照射し、反射光をライン上で受光することで高さを取得。
  * サブミクロン級のZ分解能モデルをラインアップ。
  * 金属・半導体の反射面でも影になりにくく、局所段差や高さ測定に強い。
  * センサ内部に**高さ・段差・平面度・幅・ボリューム**などの測定ツールを実装。
    → 外部PCなしでも基本的な検査が可能。

### 4.2 一般的な3Dセンサとの比較（概念）

* **レーザ三角測量方式の3Dセンサ**との比較

  * 三角法：投光と受光が斜めのため、段差による影・死角が出やすい。
  * Gocator：同軸共焦点なので、**垂直面や谷部に対しても影が出にくい**。
* **干渉計・共焦点顕微鏡との比較**

  * 干渉計・顕微鏡：nmレベルまで行けるが視野・タクトに制約。
  * Gocator：**インラインで扱いやすい解像度・視野・速度のバランス**が取れている。

### 4.3 ワイヤボンディング3D検査への適用可能性

* **精度・速度面**

  * 公称スペック上、ワイヤボンドの高さ（数百µm〜1mm程度）に対しては
    **空間分解能・スキャン速度ともに十分な範囲**。
  * 実際にワイヤボンド検査用途の適用事例も紹介されている。
* **適している用途**

  * ループ高さの設計値との偏差測定。
  * パッド／ボール周辺の段差・平坦度評価。
  * 一部工程で「2D＋高さ」の追加検査として組み込む構成。
* **注意点（実装上の課題）**

  * 装置内のレイアウトに応じて、

    * ワイヤの密集度
    * 周辺構造による死角
    * 搬送方向とライン方向の整合
      を検討する必要がある。
* **総評（暫定）**

  * **「ワイヤ高さ・段差測定用の3Dセンサ」としては有力候補**。
  * 一方で、ループ形状全体を高倍率で細かく評価する「フル3D形状検査」用途では、
    共焦点顕微鏡・干渉計との比較評価が必要。

## 5. 3DPIXA シリーズ（Chromasens / LINX）

### 5.1 概要・特長

* 方式：**ステレオ＋ラインスキャン**による3Dカメラ。
* 特長：

  * 2本のラインセンサと専用照明による高速ラインスキャン。
  * 3D形状とフルカラー画像を同時取得。
  * モデルにより、

    * **小視野・高分解能（Z分解能サブµm、Zレンジ小）**
    * **大視野・中分解能**
      などのトレードオフを選択可能。
  * PCB、BGA、半導体パッケージ、ウェブ検査などの事例が豊富。

### 5.2 Gocatorとの比較（ポイントのみ）

| 観点      | Gocator（ライン共焦点） | 3DPIXA（ステレオラインスキャン）    |
| ------- | --------------- | ---------------------- |
| 測定原理    | 共焦点方式（同軸）       | ステレオ＋ラインスキャン           |
| 出力      | 3D高さ＋強度画像       | 3D高さ＋カラー画像             |
| 性格      | 局所の高さ・段差測定に強い   | ライン全体・面全体の3D外観に強い      |
| 高分解能モデル | サブµm級Z分解能       | 同等クラスのモデルあり（Zレンジは狭くなる） |

### 5.3 ワイヤボンディング3D検査に関する所感

* **プラス面**

  * ワイヤボンドを含むパッケージ全体、BGA、モールド外観などを
    **一括で3D＋カラー検査**したい用途には非常に強力。
* **難しい点（設計上の課題）**

  * 高分解能モデルほど高さレンジが狭く、
    **高いループ全体を一度の設定でカバーするには光学設計の難易度が高い**。
  * ステレオ方式のため、
    ワイヤの向き・密集具合によってはマッチングが難しい領域が出る可能性。
  * ラインスキャン方式であるため、
    **ラインレートとステージ／搬送速度の精密な同期**が必要。
* **総評（暫定）**

  * パッケージ全体の3D外観検査プラットフォームとしては非常に魅力的。
  * ワイヤボンド単体の3D検査を主目的とする場合は、
    **光学・機構設計のハードルが高く、導入コスト・複雑さも含めた検討が必要**。

## 6. LensConnect Series（computar）

### 6.1 概要・特長

* USBケーブル1本で制御できる**モータ駆動レンズシリーズ**。
* ラインナップ：

  * 通常のCマウントレンズ
  * **テレセントリックLensConnect（フォーカス駆動式テレセン）** など。
* 主な機能：

  * フォーカス・絞りをソフトウェアから制御。
  * テレセントリックモデルでは、
    **倍率一定・歪曲ほぼ0%の特性を保ったままフォーカス移動できる**ことが売り。
  * 作動距離レンジ（WDレンジ）がカタログで明示されており、
    その範囲内でモータにより最適位置を追い込める。

### 6.2 半導体後工程での利用イメージ

* テレセントリックレンズは

  * **被写界深度が浅い**一方で、
  * 外形寸法測定や位置精度評価には必須。
* LensConnect（特にテレセン版）が効きそうなシーン：

  * 製品ごとに高さが微妙に異なるが、毎回手動でピント調整したくない工程。
  * クリーンブース内や筐体内で物理的にレンズに触りにくい装置。
  * 段替え・品種替えの多い工程で、
    **レシピごとにフォーカス位置・絞りをレシピ側で切り替えたい**場合。
* 総評：

  * 被写界深度の浅いテレセンレンズの弱点（調整の手間）を
    **モータ制御で補うアプローチ**として、試作機・多品種ラインで特に有用。

## 7. Jetson内蔵スマートカメラ（Alecs / Baumer AX）

### 7.1 共通コンセプト

* **イメージセンサ＋Jetson SoM＋産業用筐体＋I/O**を1台にまとめた「スマートカメラ」。
* 目的：

  * カメラで画像取得 → その場でAI推論 → 結果のみをホストへ送る構成にすることで、

    * 画像処理PCを削減
    * 配線・レイテンシを減らす
    * 装置構成をシンプル化

### 7.2 Allied Vision「Alecs」

* 仕様のポイント（カタログベース）：

  * センサ：Sony IMX545（12.4MP, 1/1.1型, Global Shutter）
  * SoM：**NVIDIA Jetson Orin NX 16GB**
  * オープンなLinux環境で、自前アプリを自由に構築可能
    → **「Open Smart Camera」**として位置づけ。
  * IP67対応の筐体・レンズチューブ構成（ハードな現場にも対応）。
* 強み（所感）：

  * 高解像度＋高性能SoMで、**高難度なAI推論まで1台で完結**できる。
  * 従来の「閉じたスマートカメラ」と違い、ユーザーアプリを主体としたプラットフォーム指向。

### 7.3 Baumer AXシリーズ

* 仕様イメージ：

  * Sony CMOSセンサ＋Jetson Nano / Xavier NX 搭載モデル。
  * Baumer独自SDK（neoAPI等）とJetPackベースでアプリを構築。
* 強み（所感）：

  * 解像度・SoM性能ともミドルレンジで、
    一般的なAI外観検査には十分。
  * 既存のBaumerカメラを使っている場合、移行しやすい。

### 7.4 当社視点でのメリット・デメリット

**メリット**

* ボンディング装置内の限られたスペースに、
  **小型の検査モジュール（カメラ＋AI）を独立配置**できる。
* 画像処理PCの数・スペース・電力を削減。
* 将来的なAI外観検査（キズ、汚れ、樹脂欠けなど）をユニット単位で追加しやすい。

**デメリット**

* **カメラとJetsonが一体**のため：

  * センサだけ、Jetsonだけを個別に交換／世代更新できない。
  * 故障時も基本的に「一体交換」となるため、
    **保守コスト・在庫形態がモジュール単位になる**。
* Jetson環境（OS/JetPack）のアップデートや長期サポートを
  **装置側で継続的に管理する必要がある**。
* 台数が増えると、それぞれのスマートカメラに
  アプリケーションを配布・バージョン管理する運用設計が必要。

## 8. 全体所感と今後の検討ポイント

### 8.1 全体トレンド

* **ソフトウェア**

  * HALCONに代表されるように、
    **開発環境へのAIアシスタント統合**が進行中。
  * 「コードを書く」より「仕様を会話で伝えてたたき台を作らせる」流れ。
* **ハードウェア**

  * 半導体向けに、サブミクロン級の3Dセンサが増加（Gocator, 3DPIXA等）。
  * LensConnectのような**電動レンズ／遠隔可変光学**が実用レベルで普及しつつある。
  * Jetson内蔵スマートカメラが各社から登場し、
    **エッジAI前提の構成**が現実的になってきた。

### 8.2 当社としての示唆（短〜中期）

1. **3Dボンディング検査**

   * Gocator 4000/5000系は、
     **ワイヤ高さ・段差測定には有力候補**。
     実機サンプルでの検証価値あり。
   * 3DPIXAは、パッケージ全体の3D外観検査プラットフォームとして押さえておく。

2. **光学設計**

   * LensConnectテレセンは、
     テレセントリック＋多品種対応ラインでの**フォーカス調整工数削減**に効きそう。
     今後の新規ライン／試作機で検証候補。

3. **ソフトウェア開発効率**

   * HALCON AIアシスタントは、
     HALCONベースのプロトタイピング効率向上に寄与。
   * 自社C++/Pythonフレームワーク側では、
     Copilot / ChatGPTの利用と組み合わせることで、
     **構想〜プロトタイプ〜製品コード**の全体効率を上げられる。

4. **エッジAIアーキテクチャ**

   * Alecs / Baumer AX を用いて、
     **「装置内の一部工程をスマートカメラに任せる」PoC** を小規模に実施する価値あり。
   * その際、保守性（モジュール単位交換）とバージョン管理の運用をセットで検討する必要がある。

## 9. 5分報告用 超要約（口頭用）

1. **ソフトウェア：HALCONにAIアシスタントが入った**

   * HALCON専用のCopilotのような位置づけで、
     レシピ開発やデバッグが早くなりそう。

2. **3D：Gocatorと3DPIXAがそれぞれ違う強み**

   * Gocator：ワイヤ高さやパッド段差など「局所の高さ検査」に向いたライン共焦点。
   * 3DPIXA：パッケージ全体・基板全体の3D＋カラー外観検査に強い。

3. **光学：テレセン＋電動LensConnectが実用段階**

   * 被写界深度の浅いテレセンのピント合わせを、
     ソフトから自動化できる点が実務上大きい。

4. **ハード構成：Jetsonスマートカメラが現実的な選択肢に**

   * Alecs（Orin NX 16GB）などを使えば、
     小型モジュール単位でエッジAI検査が可能。
   * ただし保守は「モジュールごと交換」の発想が必要。
